# 设计说明：为什么不改 app.asar，以及踩过的坑

v0.3.0 · 2026-11-01

## 一、问题从哪来

DSH 的 `ask_user_question` 会把聊天输入框**接管**成一张问答卡：选项、自填框、跳过/继续。
用户想顺手贴张截图说明，没有入口。

查了 `@deepseek-ai/dsh-client-ui-user-questions` 的 `inject`：

```js
const inject = ['sessions', 'remote', 'remote.userQuestions', 'uiSession', 'slots', 'locale', 'uiConversation']
```

**没有任何附件通道**。聊天输入框的附件能力在 `dsh-client-ui-chat` / `dsh-client-ui-conversation` 内部，
也没有对外暴露服务。所以卡片本身拿不到附件。

## 二、为什么选插件，不选改 asar

改 asar 只有一种做法：把卡片 bundle 改完，整包重打包（182MB、1.8 万个条目、偏移全变），
而且它正在被运行中的进程按旧偏移懒加载 —— 必须完整退出应用，写坏了 Electron 直接不启动。

这台机器上还留着上一次这么干失败的现场：

```
app.asar.purge-handoff.json → "detail": "Timed out; original archive retained. Retry handoff after a full quit."
                              "phase": "expired"
app.asar.rename-pending      残留
```

插件层的代价对比：

| | 改 asar | 插件层 |
|---|---|---|
| 生效方式 | 完整退出 + 重打包 + 重启 | 加一行 insert，热加载 |
| 失败后果 | 应用起不来 → 重装 | 插件不加载，删一行回原样 |
| DSH 升级 | 静默丢失 | 一般还在（依赖的 DOM 契约没变的话） |
| 用户看到的效果 | 一模一样 | 一模一样 |

## 三、用到的公开面

| 用途 | 面 | 备注 |
|---|---|---|
| 找卡片 | `frame[data-question-key]` | 值形如 `question:<id>:<callId>` |
| 卡片内容区 | `div[data-question-scroll]` | 选项、自填框在里面；`footer` 在外面 |
| 拿会话 | `ctx.sessions.binding(id).session` | 见坑 ① |
| 发消息 | `session.prompt(content, mode, signal, requestId)` | 和聊天输入框同一条 |
| 图片块 | `{type:'image', mediaType, data}` | `data` 是裸 base64，**不带** `data:` 前缀 |
| 文件块 | `{type:'file', receiptId}` | 先 `ctx.fileUpload.upload(...)` 拿 receipt |
| 上传 | `ctx.fileUpload.upload(sessionId, blob, name, signal, onProgress)` | 返回 `{ok, value:{receiptId, file}}` |

内容顺序照抄聊天输入框：`[...附件, {type:'text'}]`。`mode` 用 `steer`（回答完立刻插进当前这一轮），
宿主回 `steer-unavailable` 时退 `queue`。

## 四、坑

### ① 卡片 key 里那段 id 不是会话身份（线上 bug，已修）

`data-question-key` = `question:<某段 id>:<callId>`。想当然认为中间就是 sessionId，直接
`sessions.binding(那段)` —— 线上那段是**裸 uuid**，`binding()` 返回 `undefined`，于是：

```
client:paste 1
client:attach 1 item(s)
client:no-session 8933bde82114e4e273533c4045274598   ← 图没发出去
```

正确做法是按候选回落：

```
key 里那段 → uiSession.current.getSnapshot().key（真会话 id，形如 session-<uuid>）→ 列表里唯一 running 的会话
```

### ② 加载 ≠ 生效

`client:mount` 只说明插件被加载了；卡片上到底有没有那条栏，要看 `client:augment`。
两条都写进同一个日志文件，就是为了下次一眼分清。

### ③ 先提醒，再发附件

文件上传要时间。上传没完就发附件，模型可能已经开始干活了。所以：
还在上传 → 先发一条纯文字的 steer「先别动手：还有 N 个附件正在上传，收到后再继续」，等上传完再发附件。
图片是内联的，瞬间就到，不需要这一步。

### ④ 关掉不等于作答

卡片右上角 `×` 只是关面板。所以只在这两种情况下发附件：用户点过卡片主体（选项/自填框/footer），
并且卡片消失了。点 `header`、点自己的栏，都不算。

### ⑤ 栏不能塞进滚动区

一开始把栏追加进 `[data-question-scroll]`（选项容器），选项多的时候会跟着滚、视觉上像"选项的一部分"。
改成插在 `section` 里、`footer` 之前，栏就有了自己的一行，跟选项彻底分层。

### ⑥ 配置文件里的中文注释

`cordis.patch.yml` 是会被各种编辑器打开的配置文件。第一版往里写了 UTF-8 中文注释，
在 GBK 编辑器里读出来是 `瀹夸富闂瓟…`，看起来像文件损坏。现在那行注释是纯 ASCII。

### ⑦ PowerShell 写 JSON 会带 BOM

`Set-Content -Encoding UTF8` 在 PowerShell 5.1 上会写 BOM，`JSON.parse` 直接报错。
改 JSON 用 Node（`fs.writeFileSync` 默认无 BOM），或者写完校验首字节。

### ⑧ `<html lang>` 不能当界面语言用（0.3.1）

插件 bundle 往往比 locales 服务先执行。那一刻 `document.documentElement.lang` 还是模板里的 `en`，
可界面其实是中文 —— 于是栏上出现了「+ Attach / Pick options, hit Continue…」。
而且 `copy` 是模块求值时算一次的常量，之后再变也不会更新。

改成：以 `ctx.get('locale').getSnapshot().active` 为准（`zh` / `en`），
再 `locale.subscribe(...)` 订阅变化，把已经挂上去的栏就地换文案；
`document.lang` 和 `navigator.language` 只做兜底。

## 五、没做的事

- **没让附件进工具结果**。`ask_user_question` 的输出 schema 是死的：`{answers:[{id, selected, custom}]}`
  再包成一个 text 块。要带图得改宿主 + 改 typert remote 协议 + 改会话投影，最后还取决于
  provider 肯不肯在 `role:"tool"` 消息里收 image 块。粗估 25–35% 能成，收益是"图在工具结果里而不是
  紧跟着的一条消息"，不值。
- **没做拖拽**。粘贴已经覆盖大多数场景（截图 → Ctrl+V）。
- **没做多会话并发**。问答卡一次只属于一个会话，插件按卡片 key 隔离，没有额外的会话选择器。
